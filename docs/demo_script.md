## Before You Begin

**What is ONEValue?**

ONEValue is a human capital intelligence platform built for CACEIS. It takes data that already exists — performance reviews, training records, absence logs — and transforms it into behavioral signals that help managers, HR, and employees understand how sustainable value is actually created at work.

The key idea: **KPIs are not value. They are signals.** A high performance score tells you something happened. It does not tell you whether it was sustainable, whether the person is growing, or whether the team condition that produced it still exists. ONEValue goes further.

**The four roles you will demo:**

| Role | Login ID | Their question |

| Manager | `mgr_001` | "Who on my team needs support?" |
| HR | `hr_001` | "Where are the workforce risks?" |
| Product Owner / Admin | `admin_001` | "Is this system ready to deploy?" |

## Appendix A — Handling Tough Questions

**"Isn't this just a scoring system with extra steps?"**
> "No — and that distinction matters. A scoring system ranks people and stops there.
> ONEValue explicitly shows confidence alongside every score,
> refuses to interpret low-confidence profiles, and never produces an automatic HR action.
> The interpretation confidence score is what separates a signal from a conclusion."

**"What stops a manager from using this to justify a decision they've already made?"**
> "Two things: first, the system is transparent to employees — they see the same signals.
> Second, every view shows guardrails: 'These are prompts, not judgments. Validate context before acting.'
> But you're right that governance requires more than technical safeguards — it requires
> training, norms, and HR oversight. The system is designed to support that, not replace it."

**"Can this be gamed?"**
> "Any system can be gamed. An employee who knows training hours are tracked
> might take low-value courses. We address this with the learning signal design —
> it weights both training count and hours, and flags patterns that look inconsistent
> with other signals. But the deeper answer is: this system works best in a culture
> of honest conversation, not surveillance. The context-logging feature exists
> precisely so employees can flag when signals don't reflect reality."

**"What's the legal/GDPR status?"**
> "The prototype uses anonymized data. Before production deployment,
> a full GDPR compliance review is required — data minimization, consent framework,
> right to explanation, right to correction. The system's design anticipates these:
> employee transparency, data correction inputs, confidence thresholds.
> But legal sign-off is a named milestone on the roadmap, not a future assumption."

**"How is this different from what SuccessFactors / Workday already does?"**
> "Those platforms capture HR data and surface it in dashboards.
> ONEValue applies a valuation framework on top of that data — the Blue-Line model —
> that explicitly asks: is value being created sustainably?
> Most HRIS dashboards show you that someone scored 3.8 in their review.
> ONEValue asks: is that 3.8 sustainable? Is it supported by learning investment?
> Is it fragile because of workload pressure? That's a different question."

## Appendix B — Key Terms Glossary

| Term | Plain-language meaning |
|------|------------------------|
| **Blue-Line Framework** | An INSEAD research framework that says KPIs are signals, not value. Value requires sustainable, learning-oriented behavior over time. |
| **Value Potential** | A composite score: 35% contribution + 30% learning + 20% sustainability + 15% progression. Always shown with a confidence score. |
| **Interpretation Confidence** | How much data do we have? How reliable is it? Low confidence = don't interpret. |
| **Sustainability Signal** | Is this person working in a way that can continue? Derived from the inverse of absence risk. |
| **Continuity Risk** | Risk that this person's contribution will be interrupted — by burnout, departure, or workload collapse. |
| **Archetype** | A behavioral profile pattern (e.g. "Value Under Pressure", "Future Value Builder"). Not a permanent label — archetypes change as signals change. |
| **KMeans Segmentation** | An AI technique that groups employees with similar signal patterns. Used for pattern discovery, not ranking. |
| **Context Log** | A note entered by an employee or manager explaining what the data cannot capture. |
| **Reliability-Adjusted Score** | Value Potential × Interpretation Confidence. When data is poor, the adjusted score drops — forcing humility. |
